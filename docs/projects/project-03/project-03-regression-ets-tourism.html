Executive summary

NoteExecutive summary

Title: Time series regression and exponential smoothing for South African accommodation demand

Section and topic: Section 2. Time series regression (trend, seasonal dummies and Fourier terms, intervention variables, a predictor series, regression with ARIMA errors) and exponential smoothing (simple, Holt, damped trend, Holt–Winters and the ETS framework).

Type of project: Implementation and model comparison on real-world data. I code the additive Holt–Winters method from first principles (the recursions and the least squares estimation) and check it against ETS() in fable. The project uses the same series and the same test set as Project 1, so the results of the two projects can be compared directly.

Question: How well do the two main Section 2 forecasting approaches, time series regression and exponential smoothing, forecast monthly accommodation demand, and how should each of them deal with the COVID-19 collapse? Can either of them beat the Project 1 SARIMA model?

Data: Real-world, publicly available data. Statistics South Africa, Tourist Accommodation release P6410, series B64100 (stay unit nights sold, total industry), and the monthly average rand per US dollar exchange rate (FRED series EXSFUS), January 2015 to June 2026. Full source details are in Section 2.1.

Methods: Regression: a static regression with trend, seasonal dummies and COVID intervention terms, then a regression with ARIMA errors in which the intervention decay rate is chosen by profile likelihood, the seasonal form (dummies or Fourier terms) by AICc and the error model by the Box and Jenkins steps; the log exchange rate is added and forecast both ex ante and ex post. Exponential smoothing: ETS on the raw training data, then the full family of exponential smoothing methods on a series in which the COVID window is replaced by regression-based imputed values, with my own Holt–Winters code as a check. All models are diagnosed (Ljung and Box) and compared with the seasonal naive benchmark and the Project 1 SARIMA on the July 2024 to June 2026 test set and by rolling-origin cross-validation.

Key findings: See Section 7.1.

What I would do differently: Add noise to the imputed COVID values (multiple imputation) so that the exponential smoothing models do not treat them as exact, and estimate the intervention decay rate jointly with the other regression parameters rather than on a grid.

Detailed analysis: the sections below.

1 Introduction and research question

Project 1 modelled monthly nights sold with ARIMA and SARIMA models and found that the COVID-19 collapse in April 2020 was the main obstacle: keeping the COVID months broke the SARIMA model, while treating them as missing worked well. This project turns to the two other forecasting approaches from Section 2.

  • Time series regression explains the series with explanatory variables: a trend, the calendar month, variables that describe the COVID shock, and an outside series (the exchange rate). The COVID months are used rather than deleted, because the shock becomes part of the model. The main danger is that a regression assumes independent errors, which time series errors almost never are.
  • Exponential smoothing forecasts with weighted averages of past observations, with weights that decay exponentially into the past. The methods differ in which components (level, trend, season) they track. Exponential smoothing cannot skip missing values, so the COVID months must be dealt with before fitting.

A second question is whether the exchange rate helps. A weaker rand makes South Africa cheaper for foreign visitors, so the rand might carry information about demand. This links to Project 2, which models the rand’s volatility.

Research question. How accurately do time series regression and exponential smoothing forecast monthly nights sold, how should each handle the COVID-19 shock, and does either approach (or adding the exchange rate) beat the Project 1 SARIMA on the same test set?

3 Part A: Time series regression

3.1 Describing the COVID shock with intervention variables

A regression can absorb the shock if it is given explanatory variables whose shape matches how the event unfolded. This follows the transfer function idea from the notes. With \(t_0\) = April 2020 and everything on the log scale:

  • Decaying shock: \(D_t(\delta) = \delta^{\,t - t_0}\) for \(t \ge t_0\) and 0 before. Its coefficient \(\omega\) is the immediate effect in April 2020, which then dies out geometrically at rate \(\delta\). This is the transfer function \(\omega / (1 - \delta L)\) applied to a pulse at \(t_0\).
  • Pulses for March 2020 (lockdown started on 27 March, so the month was only partly affected) and May 2020 (the industry stayed almost completely closed, so the bottom of the collapse lasted two months rather than one).
  • Level shift: \(S_t = 1\) for \(t \ge t_0\), allowing a permanent difference between the pre-COVID and post-COVID levels.
Code 
covid_vars <- function(df, delta) {
  k0 <- month_num(shock_month)
  df |>
    mutate(k     = month_num(Month) - k0,
           decay = if_else(k >= 0, delta^pmax(k, 0), 0),
           mar20 = as.numeric(k == -1),
           may20 = as.numeric(k == 1),
           step  = as.numeric(k >= 0))
}

3.2 Model A1: static regression

The simplest time series regression (fpp3 Chapter 7) has a linear trend, 11 seasonal dummies and the intervention variables, with independent errors:

\[ \log y_t = \beta_0 + \beta_1 t + \sum_{j=2}^{12} \gamma_j M_{jt} + \omega D_t(\delta) + \kappa_1 P^{\text{Mar20}}_t + \kappa_2 P^{\text{May20}}_t + \lambda S_t + \varepsilon_t, \qquad \varepsilon_t \overset{iid}{\sim} N(0, \sigma^2). \]

\(\delta\) is fixed at a provisional value of 0.80 here; it is chosen properly in Section 3.3.1.

Code 
train_static <- covid_vars(train, 0.80)
test_static  <- covid_vars(test, 0.80)

fit_static <- train_static |>
  model(TSLM(log(nights) ~ trend() + season() + decay + mar20 + may20 + step))

static_glance <- glance(fit_static)
static_res    <- augment(fit_static)$.innov
dw_static     <- sum(diff(static_res)^2) / sum(static_res^2)          # Durbin-Watson
lb_static     <- Box.test(static_res, lag = 24, type = "Ljung-Box")$p.value
r1_static     <- acf(static_res, lag.max = 1, plot = FALSE)$acf[2]
Code 
fit_static |> gg_tsresiduals(lag_max = 36)

The fit looks impressive: the adjusted \(R^2\) is 0.965. The residuals tell a different story (Figure 2). They drift in long runs above and below zero, the lag 1 autocorrelation is 0.73, the Durbin–Watson statistic is 0.53 (far below the value of 2 expected for independent errors) and the Ljung and Box test on 24 lags gives p < 0.001.

This matters for more than tidiness. With positively autocorrelated errors, the least squares estimates are still unbiased but no longer efficient, the reported standard errors are too small, so the intervention terms look more significant than they are, and the prediction intervals are too narrow. The static regression also ignores useful information: if this month was above the fitted line, next month probably will be too. The remedy, following fpp3 Chapter 10, is to let the error follow an ARIMA process.

3.3 Model A2: regression with ARIMA errors

The dynamic regression replaces the independent error by an ARIMA process:

\[ \log y_t = \sum_{j=2}^{12} \gamma_j M_{jt} + \omega D_t(\delta) + \kappa_1 P^{\text{Mar20}}_t + \kappa_2 P^{\text{May20}}_t + \lambda S_t + \eta_t, \qquad (1 - L)\,\phi(L)\,\eta_t = \theta(L)\,\varepsilon_t . \]

Two choices from the static model are revisited. First, the deterministic trend is dropped in favour of a first difference in the errors: after the shock the level does not follow a straight line, and a wandering (stochastic) level is more realistic. With \(d = 1\) the intercept and trend are differenced away, which is why they do not appear. Second, the seasonality is kept deterministic (dummies) rather than handled with a seasonal difference. In Project 1, every seasonal ARIMA model fitted with the COVID months included estimated a seasonal MA coefficient at or near -1. A seasonal MA factor \((1 - L^{12})\) that cancels the seasonal difference is the classic sign that the seasonal pattern is fixed rather than evolving, so seasonal differencing would be over-differencing.

3.3.1 Choosing the decay rate by profile likelihood

The decay rate \(\delta\) enters the model non-linearly, so it cannot be estimated by ARIMA() directly. Instead I profile it: for each \(\delta\) on a grid from 0.70 to 0.96, the model is fitted (with the ARIMA error orders chosen by AICc) and the AICc recorded. The value of \(\delta\) with the smallest AICc is used. Because \(\delta\) is estimated, the model really has one more parameter than ARIMA() reports; this does not change the ranking along the grid.

Code 
delta_grid <- seq(0.70, 0.96, by = 0.02)

profile <- bind_rows(lapply(delta_grid, function(dl) {
  f <- covid_vars(train, dl) |>
    model(reg = ARIMA(log(nights) ~ season() + decay + mar20 + may20 + step +
                        pdq(d = 1) + PDQ(0, 0, 0)))
  tibble(delta = dl,
         AICc  = glance(f)$AICc,
         spec  = format(f$reg[[1]]))
}))

delta_hat <- profile$delta[which.min(profile$AICc)]
Code 
ggplot(profile, aes(delta, AICc)) +
  geom_line(colour = "grey40") +
  geom_point(colour = "grey40") +
  geom_point(data = filter(profile, delta == delta_hat), colour = "firebrick", size = 3) +
  labs(x = expression(delta), y = "AICc")

The AICc is minimised at \(\hat\delta\) = 0.76 (Figure 3). A decay rate of 0.76 means that the temporary part of the shock halves every 2.5 months and has fallen to 4% of its initial size after a year.

3.3.2 Seasonal dummies or Fourier terms?

Fourier terms (\(\sin(2\pi k t/12)\) and \(\cos(2\pi k t/12)\) for \(k = 1, \dots, K\)) are the other standard way to put seasonality into a regression. With small \(K\) they describe a smooth seasonal shape with fewer parameters; with \(K = 6\) they are equivalent to the 11 dummies. I compare the two at \(\hat\delta\) by AICc. All the models have the same response and the same order of differencing, so their AICc values are comparable.

Code 
train_reg <- covid_vars(train, delta_hat)
test_reg  <- covid_vars(test, delta_hat)

The lowest AICc belongs to the model with seasonal dummies. The low-order Fourier models are clearly worse: the accommodation seasonal pattern has a sharp December peak, a smaller Easter and mid-year bump and a dip in winter, which needs many harmonics to describe. Fourier terms pay off mainly for long seasonal periods (weekly data with period 52, or daily data), where dummies would need many more parameters. Seasonal dummies are used from here on.

The selected error model is LM w/ ARIMA(2,1,1) errors. The estimates have a direct interpretation on the log scale. The decaying shock has \(\hat\omega\) = -3.19; combined with the May 2020 pulse and the level shift, this reproduces a loss of almost all demand in April and May 2020. The level shift is \(\hat\lambda\) = -0.515 (p < 0.001). This needs careful interpretation. Because the error \(\eta_t\) has a unit root, it has its own wandering level, and the slow two-year recovery is carried by the error rather than by the intervention terms: the decaying shock dies out quickly (see the half-life above), and \(\hat\lambda\) is the part of the April 2020 drop that did not decay geometrically. It is therefore not the gap between the pre- and post-COVID levels; that gap is estimated directly in Section 4.2. Figure 5 shows the contribution of the intervention terms alone, which is why it stays flat after 2020; the recovery towards the post-COVID level happens in the error process. The standard errors are now valid only because the errors are modelled; compare the static regression, whose standard errors were too small.

3.4 Model A3: adding the exchange rate

Because the model is in logs, the coefficient on log USD/ZAR is an elasticity: a 10% weakening of the rand is associated with a change of about 2.7% in nights sold, holding the seasonal and COVID terms fixed. The estimate is 0.270 (p 0.175), and the AICc gets worse from -227.1 to -225.9. The exchange rate does not add significant information once the seasonal pattern and the COVID shock are accounted for, which is not surprising since most stays are domestic and the effect of the rand on foreign arrivals works with a lag. The errors are differenced, so the coefficient is identified from changes in the rand and changes in demand within the same month.

A regression with a predictor series has a practical catch: to forecast nights sold, I need future values of the exchange rate, which are not known when the forecast is made. Two versions are therefore evaluated:

  • Ex ante (realistic): the exchange rate is assumed to stay at its last observed value (June 2024), a naive forecast.
  • Ex post (optimistic): the actual exchange rate during the test period is used. This is not a genuine forecast, since it uses information that would not have been available in June 2024. It shows the best the model could do if the rand were forecast perfectly.

4 Part B: Exponential smoothing

4.1 Model B1: ETS on the raw training data

The ETS() function selects the error, trend and seasonal forms (additive, multiplicative or none) by AICc and estimates the smoothing parameters and initial states by maximum likelihood. Exponential smoothing cannot skip missing observations, so the first attempt simply fits ETS to the training data including the COVID months, on both the original and the log scale.

Code 
fit_ets_raw <- train |>
  model(`ETS raw (original scale)` = ETS(nights),
        `ETS raw (log scale)`      = ETS(log(nights)))

ets_par_tbl <- function(fit) {
  tidy(fit) |>
    filter(term %in% c("alpha", "beta", "gamma", "phi")) |>
    select(.model, term, estimate) |>
    pivot_wider(names_from = term, values_from = estimate) |>
    left_join(tibble(.model = names(fit),
                     Form = vapply(names(fit), function(m) format(fit[[m]][[1]]), "")),
              by = ".model") |>
    relocate(Form, .after = .model)
}

raw_tbl <- ets_par_tbl(fit_ets_raw)
alpha_raw <- raw_tbl$alpha
Code 
raw_tbl |> rename(Model = .model) |> kable(digits = 4)

This is the exponential smoothing version of the problem Project 1 had with SARIMA. On both scales the level smoothing parameter is at its upper limit (\(\hat\alpha \approx\) 1.000): the only way the method can follow a collapse of more than 95% and a two-year recovery is to reset the level to the latest observation every month. On the log scale the selected model even has no seasonal component: on the log scale the April 2020 drop is many times larger than the seasonal swings, so the likelihood gains nothing from tracking the season. A model with no seasonality for a series this seasonal is clearly wrong. With \(\alpha = 1\) the forecasts are simply the last observation (plus the seasonal pattern, if there is one), the residual variance is inflated by the COVID months and the prediction intervals are very wide. The COVID window has to be dealt with before exponential smoothing can work.

4.2 Imputing the COVID window with a regression

Three ways of handling the window are possible: (1) fit only to the post-COVID months, which leaves just over two years of data to estimate 12 seasonal effects; (2) remove the estimated intervention effect from Part A; or (3) replace the COVID months by values that describe what demand would have looked like without the pandemic. Option (2) does not help much: the regression explains the shock partly through its ARIMA error, so the “adjusted” series still contains most of the recovery dynamics. I therefore use option (3), with a regression as the imputation model.

The imputation regression is fitted only to the non-COVID months:

\[ \log y_t = \beta_0 + \beta_1 t + \sum_{j=2}^{12} \gamma_j M_{jt} + \lambda R_t + \varepsilon_t, \]

where \(R_t\) is a ramp: 0 before March 2020, 1 after March 2022, and rising linearly through the window. Since \(R_t\) only takes the values 0 and 1 in the months used for fitting, \(\lambda\) is the difference between the pre- and post-COVID levels; inside the window the ramp produces a straight-line transition between the two levels, with the usual seasonal pattern on top. The fitted values in the window are used as the imputed values.

4.3 Model B2: Holt–Winters from first principles

To make sure I understand what ETS() is doing, I implement the additive Holt–Winters method myself (fpp3 Section 8.3). With \(y_t\) the log of the imputed series, \(\ell_t\) the level, \(b_t\) the trend and \(s_t\) the seasonal effect, the one-step forecast and the error are

\[ \hat y_{t \mid t-1} = \ell_{t-1} + b_{t-1} + s_{t-12}, \qquad e_t = y_t - \hat y_{t \mid t-1}, \]

and the components are updated in error-correction form:

\[ \begin{aligned} \ell_t &= \ell_{t-1} + b_{t-1} + \alpha e_t, \\ b_t &= b_{t-1} + \beta e_t, \\ s_t &= s_{t-12} + \gamma e_t . \end{aligned} \]

Each update moves a component in the direction of the latest error, and the smoothing parameters say how far. The \(h\)-step forecast is \(\hat y_{T+h \mid T} = \ell_T + h\, b_T + s_{T+h-12k}\), where \(k\) makes the seasonal index refer to the last observed year. With additive errors, maximising the Gaussian likelihood is the same as minimising the sum of squared one-step errors (the error variance can be profiled out), so I estimate the three smoothing parameters and the 13 free initial states (\(\ell_0\), \(b_0\) and 11 seasonal effects; the 12th is set so the seasonal effects sum to zero) by minimising the SSE with optim(). The parameter bounds match those in fable (between 0.0001 and 0.9999).

Code 
# Additive Holt-Winters filter -------------------------------------------
# par = (alpha, beta, gamma, l0, b0, s_{-11}, ..., s_{-1});
# the last seasonal state s_0 makes the 12 initial effects sum to zero.
hw_filter <- function(par, y, m = 12) {
  alpha <- par[1]; beta <- par[2]; gamma <- par[3]
  level <- par[4]; trend <- par[5]
  s     <- c(par[6:(4 + m)], -sum(par[6:(4 + m)]))  # s[1] is the effect for the next month
  n <- length(y); e <- yhat <- numeric(n)
  for (t in 1:n) {
    yhat[t] <- level + trend + s[1]
    e[t]    <- y[t] - yhat[t]
    new_level <- level + trend + alpha * e[t]
    trend     <- trend + beta * e[t]
    s         <- c(s[-1], s[1] + gamma * e[t])        # rotate the seasonal states
    level     <- new_level
  }
  list(e = e, fitted = yhat, level = level, trend = trend, season = s)
}

hw_forecast <- function(state, h, m = 12) {
  state$level + (1:h) * state$trend + rep(state$season, length.out = h)
}

5.3 Results

Overall ranking. On the test set the lowest RMSE is achieved by the Damped HW model (72.5 thousand nights). Among the models that passed the diagnostic step, the best is Damped HW. For reference, the Project 1 SARIMA has an RMSE of 101.6 and the seasonal naive benchmark 132.6. In cross-validation the best model is SARIMA (Project 1) (RMSE 83.5), followed by Damped HW (89.5), with seasonal naive at 112.2 (Table 7, Figure 10). The two evaluations therefore do not fully agree, which is exactly why a single test set is not enough: the cross-validation forecasts start later (up to June 2025) and are at most 12 months ahead, so they reward models that track the recent level and penalise less for how the trend is extrapolated in the second year.

Static regression. The static regression has an RMSE of 233.8, worse than seasonal naive. Its deterministic trend is estimated from the whole training period, including the gentle decline before 2020, and is extrapolated through the test period, so the forecasts drift away from the data. Its 95% intervals happen to cover 100% of the test months, but only because the COVID months inflate the residual variance; with autocorrelated errors the interval formula itself is not valid, so this coverage cannot be relied on.

Regression with ARIMA errors. Modelling the error process gives an RMSE of 98.8 and a MAPE of 4.51%, better than the Project 1 SARIMA. Its intervals cover 100% of the test months at the 95% level and 100% at the 80% level. By June 2024 the temporary part of the shock had died out (\(\hat\delta^{\,50} \approx\) 1.1e-06), so the forecasts rest on the post-COVID level and the seasonal dummies. The main advantage of this model is interpretation: it estimates the size, shape and persistence of the shock (Figure 5) instead of discarding it.

Exchange rate. Adding the rand changes the RMSE to 106.2 ex ante and 130.3 ex post. Neither version improves on the model without the exchange rate; surprisingly, the ex post version is the worse of the two, which suggests the estimated elasticity does not hold up in the test period. A regression’s forecasts are only as good as the forecasts (and the stability) of its explanatory variables.

Exponential smoothing on the raw data. ETS fitted with the COVID months included reaches an RMSE of 130.0, only just beating seasonal naive. With \(\hat\alpha = 1\) it is close to a seasonal random walk, and its 95% intervals are on average 2,292 thousand nights wide, against 1,060 for the regression.

Exponential smoothing on the imputed series. Imputing the window transforms exponential smoothing. The best of the seasonal models on the test set is Damped HW (RMSE 72.5), and the ranking among them is decided by the trend: the undamped Holt–Winters model (RMSE 151.7) extrapolates a fixed negative slope for two years, the no-trend model (RMSE 95.9) holds the level flat, and the damped model (RMSE 72.5) lets the slope fade. AICc preferred Holt-Winters, which is a useful reminder that AICc measures one-step-ahead fit in the training data, while the test set measures forecasts up to 24 months ahead, where the treatment of the trend dominates. The undamped model’s intervals also cover only 88% of the test months at the 95% level: its forecasts drift away from the data while the intervals stay narrow, partly because the noise-free imputed months shrink the estimated error variance. SES, which ignores the season, is far behind (RMSE 225.9), confirming the diagnostics.

7 Discussion

7.1 Key findings

  1. A static regression is not enough. Trend, seasonal dummies and intervention terms give an adjusted \(R^2\) of 0.965, but the residuals are strongly autocorrelated (Durbin–Watson 0.53), so the standard errors and intervals cannot be trusted. Its test RMSE was 233.8.
  2. Regression with ARIMA errors fixes this. With deterministic seasonal dummies (preferred to Fourier terms by AICc), a decaying intervention with \(\hat\delta\) = 0.76 (half-life about 2.5 months), two pulses and a level shift, the innovations are white noise (Ljung and Box p = 0.556), and the test RMSE is 98.8 against 101.6 for the Project 1 SARIMA. The shock is described with five parameters instead of 25 deleted months. The post-COVID level is estimated (by the imputation regression) to be 21% below the pre-COVID path.
  3. The exchange rate had an estimated elasticity of 0.270 (p 0.175) and did not improve the realistic (ex ante) forecasts.
  4. Exponential smoothing breaks on the raw data. With the COVID months included, the level smoothing parameter goes to 1 and, on the log scale, AICc even drops the seasonal component.
  5. Regression imputation rescues exponential smoothing. On the imputed series the seasonal models pass the diagnostics, and Damped HW reached a test RMSE of 72.5. The trend assumption (none, linear or damped) is what separates the seasonal models over a two-year horizon.
  6. My own Holt–Winters code reproduces ETS(). The SSE agrees to 0.46% and both put \(\beta\) and \(\gamma\) at the boundary, confirming a fixed seasonal pattern and slope.
  7. Overall, the best model on the test set was Damped HW, the best that also passed the diagnostics was Damped HW, and the best in cross-validation was SARIMA (Project 1). Among the Section 2 models, Damped HW was the most accurate in cross-validation, so the Project 1 SARIMA remains a very strong benchmark: regression and exponential smoothing match it, but only beat it clearly on one of the two evaluations.

7.2 Issues and limitations

  • The imputed values are treated as data. Exponential smoothing sees the 25 imputed months as exact observations with no noise. This makes the estimated error variance too small (so the intervals are too narrow) and can pull the smoothing parameters, since the imputed stretch is perfectly smooth. Multiple imputation (adding resampled residuals to the imputed values and averaging over many fits) would address this.
  • The imputation model is a modelling choice. The linear ramp between the pre- and post-COVID levels is a simple assumption. A different path (for example a faster or slower recovery) would change the imputed level in 2021 and, through the smoothing, the estimated slope.
  • Choice of intervention shape. The decay, pulses and step were chosen by looking at the data, so there is a risk of over-fitting the shape of the shock to this series. The pulse months were picked by eye.
  • Confounding with the exchange rate. The rand depreciated sharply in March and April 2020, at the same time as the lockdown, so the exchange rate effect is estimated mainly from the non-COVID months. It also enters without a lag, although foreign visitors book weeks or months ahead.
  • Profile likelihood standard errors. Treating \(\hat\delta\) as known when computing the other standard errors understates their uncertainty.
  • Cross-validation shortcuts. The regression’s \(\delta\) and error orders, and the ETS forms, were held fixed across origins, which favours them slightly because they were chosen with the full training set.

7.3 What I would do differently

I would use multiple imputation for the COVID window so that the exponential smoothing intervals reflect the uncertainty in the imputed values, estimate \(\delta\) jointly with the other regression parameters by maximising the likelihood directly, and try a lagged exchange rate. A cleaner solution to both problems is a model that can skip the missing months without imputing them and that has the regression and smoothing ideas built in, which is what the state space models in Project 4 provide.

# Introduction and research question

# Part A: Time series regression

## Describing the COVID shock with intervention variables

A regression can absorb the shock if it is given explanatory variables whose shape matches how the event unfolded. This follows the transfer function idea from the notes. With $t_0$ = April 2020 and everything on the log scale:

* **Decaying shock:** $D_t(\delta) = \delta^{\,t - t_0}$ for $t \ge t_0$ and 0 before. Its coefficient $\omega$ is the immediate effect in April 2020, which then dies out geometrically at rate $\delta$. This is the transfer function $\omega / (1 - \delta L)$ applied to a pulse at $t_0$.
* **Pulses** for March 2020 (lockdown started on 27 March, so the month was only partly affected) and May 2020 (the industry stayed almost completely closed, so the bottom of the collapse lasted two months rather than one).
* **Level shift:** $S_t = 1$ for $t \ge t_0$, allowing a permanent difference between the pre-COVID and post-COVID levels.

```{r}
#| label: covid-vars

covid_vars <- function(df, delta) {
  k0 <- month_num(shock_month)
  df |>
    mutate(k     = month_num(Month) - k0,
           decay = if_else(k >= 0, delta^pmax(k, 0), 0),
           mar20 = as.numeric(k == -1),
           may20 = as.numeric(k == 1),
           step  = as.numeric(k >= 0))
}
```

## Model A1: static regression

The simplest time series regression (fpp3 Chapter 7) has a linear trend, 11 seasonal dummies and the intervention variables, with independent errors:

$$
\log y_t = \beta_0 + \beta_1 t + \sum_{j=2}^{12} \gamma_j M_{jt} + \omega D_t(\delta) + \kappa_1 P^{\text{Mar20}}_t + \kappa_2 P^{\text{May20}}_t + \lambda S_t + \varepsilon_t, \qquad \varepsilon_t \overset{iid}{\sim} N(0, \sigma^2).
$$

$\delta$ is fixed at a provisional value of 0.80 here; it is chosen properly in @sec-profile.

```{r}
#| label: fit-static

train_static <- covid_vars(train, 0.80)
test_static  <- covid_vars(test, 0.80)

fit_static <- train_static |>
  model(TSLM(log(nights) ~ trend() + season() + decay + mar20 + may20 + step))

static_glance <- glance(fit_static)
static_res    <- augment(fit_static)$.innov
dw_static     <- sum(diff(static_res)^2) / sum(static_res^2)          # Durbin-Watson
lb_static     <- Box.test(static_res, lag = 24, type = "Ljung-Box")$p.value
r1_static     <- acf(static_res, lag.max = 1, plot = FALSE)$acf[2]
```

The fit looks impressive: the adjusted $R^2$ is `r fmt(static_glance$adj_r_squared, 3)`. The residuals tell a different story (@fig-static-resid). They drift in long runs above and below zero, the lag 1 autocorrelation is `r fmt(r1_static, 2)`, the Durbin–Watson statistic is `r fmt(dw_static, 2)` (far below the value of 2 expected for independent errors) and the Ljung and Box test on 24 lags gives p `r pfmt(lb_static)`.

This matters for more than tidiness. With positively autocorrelated errors, the least squares estimates are still unbiased but no longer efficient, the reported standard errors are too small, so the intervention terms look more significant than they are, and the prediction intervals are too narrow. The static regression also ignores useful information: if this month was above the fitted line, next month probably will be too. The remedy, following fpp3 Chapter 10, is to let the error follow an ARIMA process.

## Model A2: regression with ARIMA errors

The dynamic regression replaces the independent error by an ARIMA process:

$$
\log y_t = \sum_{j=2}^{12} \gamma_j M_{jt} + \omega D_t(\delta) + \kappa_1 P^{\text{Mar20}}_t + \kappa_2 P^{\text{May20}}_t + \lambda S_t + \eta_t, \qquad (1 - L)\,\phi(L)\,\eta_t = \theta(L)\,\varepsilon_t .
$$

Two choices from the static model are revisited. First, the deterministic trend is dropped in favour of a first difference in the errors: after the shock the level does not follow a straight line, and a wandering (stochastic) level is more realistic. With $d = 1$ the intercept and trend are differenced away, which is why they do not appear. Second, the seasonality is kept *deterministic* (dummies) rather than handled with a seasonal difference. In Project 1, every seasonal ARIMA model fitted with the COVID months included estimated a seasonal MA coefficient at or near -1. A seasonal MA factor $(1 - L^{12})$ that cancels the seasonal difference is the classic sign that the seasonal pattern is fixed rather than evolving, so seasonal differencing would be over-differencing.

### Choosing the decay rate by profile likelihood {#sec-profile}

The decay rate $\delta$ enters the model non-linearly, so it cannot be estimated by `ARIMA()` directly. Instead I profile it: for each $\delta$ on a grid from 0.70 to 0.96, the model is fitted (with the ARIMA error orders chosen by AICc) and the AICc recorded. The value of $\delta$ with the smallest AICc is used. Because $\delta$ is estimated, the model really has one more parameter than `ARIMA()` reports; this does not change the ranking along the grid.

```{r}
#| label: profile-delta

delta_grid <- seq(0.70, 0.96, by = 0.02)

profile <- bind_rows(lapply(delta_grid, function(dl) {
  f <- covid_vars(train, dl) |>
    model(reg = ARIMA(log(nights) ~ season() + decay + mar20 + may20 + step +
                        pdq(d = 1) + PDQ(0, 0, 0)))
  tibble(delta = dl,
         AICc  = glance(f)$AICc,
         spec  = format(f$reg[[1]]))
}))

delta_hat <- profile$delta[which.min(profile$AICc)]
```

A decay rate of `r fmt(delta_hat, 2)` means that the temporary part of the shock halves every `r fmt(log(0.5) / log(delta_hat), 1)` months and has fallen to `r pct(delta_hat^12)` of its initial size after a year. `r if (delta_hat <= min(delta_grid) + 1e-8) "The minimum is at the edge of the grid, so a smaller value cannot be ruled out." else ""`

### Seasonal dummies or Fourier terms?

Fourier terms ($\sin(2\pi k t/12)$ and $\cos(2\pi k t/12)$ for $k = 1, \dots, K$) are the other standard way to put seasonality into a regression. With small $K$ they describe a smooth seasonal shape with fewer parameters; with $K = 6$ they are equivalent to the 11 dummies. I compare the two at $\hat\delta$ by AICc. All the models have the same response and the same order of differencing, so their AICc values are comparable.


## Imputing the COVID window with a regression {#sec-impute}

Three ways of handling the window are possible: (1) fit only to the post-COVID months, which leaves just over two years of data to estimate 12 seasonal effects; (2) remove the estimated intervention effect from Part A; or (3) replace the COVID months by values that describe what demand would have looked like without the pandemic. Option (2) does not help much: the regression explains the shock partly through its ARIMA error, so the "adjusted" series still contains most of the recovery dynamics. I therefore use option (3), with a regression as the imputation model.

The imputation regression is fitted only to the **non-COVID** months:

$$
\log y_t = \beta_0 + \beta_1 t + \sum_{j=2}^{12} \gamma_j M_{jt} + \lambda R_t + \varepsilon_t,
$$

where $R_t$ is a ramp: 0 before March 2020, 1 after March 2022, and rising linearly through the window. Since $R_t$ only takes the values 0 and 1 in the months used for fitting, $\lambda$ is the difference between the pre- and post-COVID levels; inside the window the ramp produces a straight-line transition between the two levels, with the usual seasonal pattern on top. The fitted values in the window are used as the imputed values.

```{r}
#| label: impute

impute_covid <- function(df) {
  n_win <- month_num(covid_end) - month_num(covid_start) + 2
  df <- df |>
    as_tibble() |>
    mutate(t      = row_number(),
           mon    = factor(month(as.Date(Month))),
           in_win = Month >= covid_start & Month <= covid_end,
           ramp   = pmin(pmax((month_num(Month) - month_num(covid_start) + 1) / n_win, 0), 1),
           y_obs  = if_else(in_win, NA_real_, log(nights)))
  fit <- lm(y_obs ~ t + mon + ramp, data = df)   # lm drops the NA months
  df |>
    mutate(log_fit     = predict(fit, newdata = df),
           nights_imp  = if_else(in_win, exp(log_fit), nights)) |>
    select(-t, -mon, -y_obs, -log_fit)
}
```

## Model B2: Holt–Winters from first principles

To make sure I understand what `ETS()` is doing, I implement the additive Holt–Winters method myself (fpp3 Section 8.3). With $y_t$ the log of the imputed series, $\ell_t$ the level, $b_t$ the trend and $s_t$ the seasonal effect, the one-step forecast and the error are

$$
\hat y_{t \mid t-1} = \ell_{t-1} + b_{t-1} + s_{t-12}, \qquad e_t = y_t - \hat y_{t \mid t-1},
$$

and the components are updated in error-correction form:

$$
\begin{aligned}
\ell_t &= \ell_{t-1} + b_{t-1} + \alpha e_t, \\
b_t    &= b_{t-1} + \beta e_t, \\
s_t    &= s_{t-12} + \gamma e_t .
\end{aligned}
$$

Each update moves a component in the direction of the latest error, and the smoothing parameters say how far. The $h$-step forecast is $\hat y_{T+h \mid T} = \ell_T + h\, b_T + s_{T+h-12k}$, where $k$ makes the seasonal index refer to the last observed year. With additive errors, maximising the Gaussian likelihood is the same as minimising the sum of squared one-step errors (the error variance can be profiled out), so I estimate the three smoothing parameters and the 13 free initial states ($\ell_0$, $b_0$ and 11 seasonal effects; the 12th is set so the seasonal effects sum to zero) by minimising the SSE with `optim()`. The parameter bounds match those in `fable` (between 0.0001 and 0.9999).

```{r}
#| label: own-hw

# Additive Holt-Winters filter -------------------------------------------
# par = (alpha, beta, gamma, l0, b0, s_{-11}, ..., s_{-1});
# the last seasonal state s_0 makes the 12 initial effects sum to zero.
hw_filter <- function(par, y, m = 12) {
  alpha <- par[1]; beta <- par[2]; gamma <- par[3]
  level <- par[4]; trend <- par[5]
  s     <- c(par[6:(4 + m)], -sum(par[6:(4 + m)]))  # s[1] is the effect for the next month
  n <- length(y); e <- yhat <- numeric(n)
  for (t in 1:n) {
    yhat[t] <- level + trend + s[1]
    e[t]    <- y[t] - yhat[t]
    new_level <- level + trend + alpha * e[t]
    trend     <- trend + beta * e[t]
    s         <- c(s[-1], s[1] + gamma * e[t])        # rotate the seasonal states
    level     <- new_level
  }
  list(e = e, fitted = yhat, level = level, trend = trend, season = s)
}

hw_forecast <- function(state, h, m = 12) {
  state$level + (1:h) * state$trend + rep(state$season, length.out = h)
}

# Estimation by least squares --------------------------------------------
y_imp <- log(train_imp$nights_imp)
sse   <- function(par) sum(hw_filter(par, y_imp)$e^2)

# Starting values: classical decomposition of the first two years
first2 <- y_imp[1:24]
s_init <- y_imp[1:12] - mean(y_imp[1:12])
start  <- c(0.3, 0.01, 0.1,
            mean(first2[1:12]), (mean(first2[13:24]) - mean(first2[1:12])) / 12,
            (s_init - mean(s_init))[1:11])

own_opt <- optim(start, sse, method = "L-BFGS-B",
                 lower = c(rep(1e-4, 3), rep(-Inf, 13)),
                 upper = c(rep(0.9999, 3), rep(Inf, 13)),
                 control = list(maxit = 10000))
own_hw  <- hw_filter(own_opt$par, y_imp)

# The same model in fable --------------------------------------------------
fit_hw_fable <- train_imp |>
  model(HW = ETS(log(nights_imp) ~ error("A") + trend("A") + season("A")))

fable_sse <- sum(augment(fit_hw_fable)$.innov^2)
fp <- function(t) fable_par$estimate[fable_par$term == t]
```

## Rolling-origin cross-validation

A single 24-month test set gives one realisation of each model's forecast errors, so the ranking could be luck. As in Project 1, I also use an expanding window: the models are refitted at each of 13 origins from June 2024 to June 2025 and forecast 1 to 12 months ahead, and the errors are averaged by horizon. The imputation regression is refitted at every origin. To keep the computation manageable, the regression keeps $\hat\delta$ and its ARIMA error orders fixed at the values chosen above; the ETS forms are also fixed, but all parameters are re-estimated. The exchange rate model is left out, since its ex ante forecasts would need a rand forecast at every origin.

```{r}
#| label: cv
#| cache: true

reg_pdq <- fit_reg$Reg[[1]]$fit$spec
cv_origins <- 13
cv_h       <- 12

cv_data <- nights_sold |>
  stretch_tsibble(.init = nrow(train), .step = 1) |>
  filter(.id <= cv_origins)

cv_fc <- bind_rows(lapply(seq_len(cv_origins), function(i) {
  d   <- cv_data |> filter(.id == i) |> select(-.id)
  fut <- new_data(d, cv_h)

  # seasonal naive and Project 1 SARIMA
  dB <- d |> mutate(nights = if_else(period == "COVID window", NA_real_, nights))
  f1 <- forecast(d  |> model(`Seasonal naive` = SNAIVE(nights)), h = cv_h)
  f2 <- forecast(dB |> model(`SARIMA (Project 1)` =
                               ARIMA(log(nights) ~ 0 + pdq(0, 1, 1) + PDQ(0, 1, 1))), h = cv_h)

  # regression with ARIMA errors (orders fixed)
  dR <- covid_vars(d, delta_hat)
  fR <- covid_vars(fut, delta_hat)
  f3 <- forecast(dR |> model(Reg = ARIMA(log(nights) ~ season() + decay + mar20 + may20 + step +
                                           pdq(reg_pdq$p, 1, reg_pdq$q) + PDQ(0, 0, 0))),
                 new_data = fR)

  # exponential smoothing on the imputed series
  dI <- impute_covid(d) |> as_tsibble(index = Month)
  f4 <- forecast(dI |> model(
    `ETS(A,N,A)`   = ETS(log(nights_imp) ~ error("A") + trend("N")  + season("A")),
    `Holt-Winters` = ETS(log(nights_imp) ~ error("A") + trend("A")  + season("A")),
    `Damped HW`    = ETS(log(nights_imp) ~ error("A") + trend("Ad") + season("A"))),
    h = cv_h)

  bind_rows(as_tibble(f1), as_tibble(f2), as_tibble(f3), as_tibble(f4)) |>
```

## Results

**Overall ranking.** On the test set the lowest RMSE is achieved by the **`r best_all`** model (`r fmt(rg(best_all, "RMSE"))` thousand nights). Among the models that passed the diagnostic step, the best is **`r best_cand`**. For reference, the Project 1 SARIMA has an RMSE of `r fmt(rg("SARIMA (Project 1)", "RMSE"))` and the seasonal naive benchmark `r fmt(rg("Seasonal naive", "RMSE"))`. In cross-validation the best model is **`r cv_best`** (RMSE `r fmt(cvr(cv_best))`)`r if (cv_best != "SARIMA (Project 1)") paste0(", against ", fmt(cvr("SARIMA (Project 1)")), " for the Project 1 SARIMA") else paste0(", followed by ", cv_overall$Model[2], " (", fmt(cv_overall$RMSE[2]), ")")`, with seasonal naive at `r fmt(cvr("Seasonal naive"))` (@tbl-cv, @fig-cv). The two evaluations therefore do not fully agree, which is exactly why a single test set is not enough: the cross-validation forecasts start later (up to June 2025) and are at most 12 months ahead, so they reward models that track the recent level and penalise less for how the trend is extrapolated in the second year.

**Static regression.** The static regression has an RMSE of `r fmt(rg("Static regression", "RMSE"))`, `r if (beats_sn("Static regression")) "beating seasonal naive despite its autocorrelated errors" else "worse than seasonal naive"`. Its deterministic trend is estimated from the whole training period, including the gentle decline before 2020, and is extrapolated through the test period, so the forecasts drift away from the data. Its 95% intervals happen to cover `r pct(rg("Static regression", "cover95"))` of the test months, but only because the COVID months inflate the residual variance; with autocorrelated errors the interval formula itself is not valid, so this coverage cannot be relied on.

**Regression with ARIMA errors.** Modelling the error process gives an RMSE of `r fmt(rg("Reg", "RMSE"))` and a MAPE of `r fmt(rg("Reg", "MAPE"), 2)`%, `r if (rg("Reg", "RMSE") < rg("SARIMA (Project 1)", "RMSE")) "better than" else "slightly worse than"` the Project 1 SARIMA. Its intervals cover `r pct(rg("Reg", "cover95"))` of the test months at the 95% level and `r pct(rg("Reg", "cover80"))` at the 80% level. By June 2024 the temporary part of the shock had died out ($\hat\delta^{\,50} \approx$ `r formatC(delta_hat^50, format = "e", digits = 1)`), so the forecasts rest on the post-COVID level and the seasonal dummies. The main advantage of this model is *interpretation*: it estimates the size, shape and persistence of the shock (@fig-intervention) instead of discarding it.

**Exchange rate.** Adding the rand changes the RMSE to `r fmt(rg("Reg + ZAR (ex ante)", "RMSE"))` ex ante and `r fmt(rg("Reg + ZAR (ex post)", "RMSE"))` ex post. `r if (rg("Reg + ZAR (ex post)", "RMSE") < rg("Reg", "RMSE") && rg("Reg + ZAR (ex ante)", "RMSE") >= rg("Reg", "RMSE")) "The exchange rate only helps when its future values are known, which is never the case in practice, so the realistic (ex ante) model is not an improvement." else if (rg("Reg + ZAR (ex ante)", "RMSE") < rg("Reg", "RMSE")) "Even the realistic ex ante version improves on the model without the exchange rate, although with a single test period this difference should be interpreted cautiously." else "Neither version improves on the model without the exchange rate; surprisingly, the ex post version is the worse of the two, which suggests the estimated elasticity does not hold up in the test period."` A regression's forecasts are only as good as the forecasts (and the stability) of its explanatory variables.

**Exponential smoothing on the raw data.** ETS fitted with the COVID months included reaches an RMSE of `r fmt(rg("ETS raw (original scale)", "RMSE"))`, `r if (beats_sn("ETS raw (original scale)")) "only just beating" else "not beating"` seasonal naive. With $\hat\alpha = 1$ it is close to a seasonal random walk, and its 95% intervals are on average `r fmt(rg("ETS raw (original scale)", "width95"), 0)` thousand nights wide, against `r fmt(rg("Reg", "width95"), 0)` for the regression.

**Exponential smoothing on the imputed series.** Imputing the window transforms exponential smoothing. The best of the seasonal models on the test set is **`r best_ets`** (RMSE `r fmt(rg(best_ets, "RMSE"))`), and the ranking among them is decided by the trend: the undamped Holt–Winters model (RMSE `r fmt(rg("Holt-Winters", "RMSE"))`) extrapolates a fixed negative slope for two years, the no-trend model (RMSE `r fmt(rg("ETS(A,N,A)", "RMSE"))`) holds the level flat, and the damped model (RMSE `r fmt(rg("Damped HW", "RMSE"))`) lets the slope fade. `r if (best_aicc != best_ets) paste0("AICc preferred ", best_aicc, ", which is a useful reminder that AICc measures one-step-ahead fit in the training data, while the test set measures forecasts up to 24 months ahead, where the treatment of the trend dominates.") else "Here AICc and the test set agree."` The undamped model's intervals also cover only `r pct(rg("Holt-Winters", "cover95"))` of the test months at the 95% level: its forecasts drift away from the data while the intervals stay narrow, partly because the noise-free imputed months shrink the estimated error variance. SES, which ignores the season, is far behind (RMSE `r fmt(rg("SES", "RMSE"))`), confirming the diagnostics.

# Discussion

## Key findings {#sec-findings}

1. **A static regression is not enough.** Trend, seasonal dummies and intervention terms give an adjusted $R^2$ of `r fmt(static_glance$adj_r_squared, 3)`, but the residuals are strongly autocorrelated (Durbin–Watson `r fmt(dw_static, 2)`), so the standard errors and intervals cannot be trusted. Its test RMSE was `r fmt(rg("Static regression", "RMSE"))`.
2. **Regression with ARIMA errors fixes this.** With deterministic seasonal dummies (preferred to Fourier terms by AICc), a decaying intervention with $\hat\delta$ = `r fmt(delta_hat, 2)` (half-life about `r fmt(log(0.5) / log(delta_hat), 1)` months), two pulses and a level shift, the innovations are white noise (Ljung and Box p = `r pfmt(lbp("Reg"))`), and the test RMSE is `r fmt(rg("Reg", "RMSE"))` against `r fmt(rg("SARIMA (Project 1)", "RMSE"))` for the Project 1 SARIMA. The shock is described with five parameters instead of 25 deleted months. The post-COVID level is estimated (by the imputation regression) to be `r pct(1 - exp(imp_ramp), 0)` below the pre-COVID path.
3. **The exchange rate** had an estimated elasticity of `r fmt(b_zar, 3)` (p `r pfmt(p_zar)`) and `r if (rg("Reg + ZAR (ex ante)", "RMSE") < rg("Reg", "RMSE")) "improved" else "did not improve"` the realistic (ex ante) forecasts.
4. **Exponential smoothing breaks on the raw data.** With the COVID months included, the level smoothing parameter goes to 1 and, on the log scale, AICc even drops the seasonal component.
5. **Regression imputation rescues exponential smoothing.** On the imputed series the seasonal models pass the diagnostics, and `r best_ets` reached a test RMSE of `r fmt(rg(best_ets, "RMSE"))`. The trend assumption (none, linear or damped) is what separates the seasonal models over a two-year horizon.
6. **My own Holt–Winters code reproduces `ETS()`.** The SSE agrees to `r fmt(abs(own_opt$value - fable_sse) / fable_sse * 100, 2)`% and both put $\beta$ and $\gamma$ at the boundary, confirming a fixed seasonal pattern and slope.
7. **Overall,** the best model on the test set was `r best_all`, the best that also passed the diagnostics was `r best_cand`, and the best in cross-validation was `r cv_best`. `r if (cv_best == "SARIMA (Project 1)") paste0("Among the Section 2 models, ", cv_overall$Model[cv_overall$Model != "SARIMA (Project 1)"][1], " was the most accurate in cross-validation, so the Project 1 SARIMA remains a very strong benchmark: regression and exponential smoothing match it, but only beat it clearly on one of the two evaluations.") else ""`

## Issues and limitations

* **The imputed values are treated as data.** Exponential smoothing sees the 25 imputed months as exact observations with no noise. This makes the estimated error variance too small (so the intervals are too narrow) and can pull the smoothing parameters, since the imputed stretch is perfectly smooth. Multiple imputation (adding resampled residuals to the imputed values and averaging over many fits) would address this.
* **The imputation model is a modelling choice.** The linear ramp between the pre- and post-COVID levels is a simple assumption. A different path (for example a faster or slower recovery) would change the imputed level in 2021 and, through the smoothing, the estimated slope.
* **Choice of intervention shape.** The decay, pulses and step were chosen by looking at the data, so there is a risk of over-fitting the shape of the shock to this series. The pulse months were picked by eye.
* **Confounding with the exchange rate.** The rand depreciated sharply in March and April 2020, at the same time as the lockdown, so the exchange rate effect is estimated mainly from the non-COVID months. It also enters without a lag, although foreign visitors book weeks or months ahead.
* **Profile likelihood standard errors.** Treating $\hat\delta$ as known when computing the other standard errors understates their uncertainty.
* **Cross-validation shortcuts.** The regression's $\delta$ and error orders, and the ETS forms, were held fixed across origins, which favours them slightly because they were chosen with the full training set.

## What I would do differently

I would use multiple imputation for the COVID window so that the exponential smoothing intervals reflect the uncertainty in the imputed values, estimate $\delta$ jointly with the other regression parameters by maximising the likelihood directly, and try a lagged exchange rate. A cleaner solution to both problems is a model that can skip the missing months without imputing them and that has the regression and smoothing ideas built in, which is what the state space models in Project 4 provide.
